# Horse Profile / BASE data audit

監査日: 2026-11-08  
対象DB: `data/raw/race.db`  
対象母集団: `headDataKubun='7'` のJRA平地レース・出走馬。件数は必要に応じて2015年以降に限定。

## 1. 参照実装とデータ経路

- 生データはSQLiteの `NL_RA_RACE`（レース）と `NL_SE_RACE_UMA`（出走馬・結果）を使う。馬マスタ `NL_UM_UMA` に血統祖先IDらしき `Ketto3Info*HansyokuNum` がある。
- `raceverse/adapters/race_data.py` は `Time` を分・秒・0.1秒形式から秒へ変換し、`HaronTimeL3` を0.1秒から秒へ変換する。レース別のラップ列 `LapTime0..24` はあるが、個体別ラップ列は参照実装にもデータ上にもない。
- 確定済み結果は出走馬側で `headDataKubun='7'` かつ `KakuteiJyuni > 0` に限定する。取消・中止等は完走時計の学習行として扱わない。
- `raceverse/adapters/existing_ability.py` は既存Rankerを変更せず、時系列OOFスコアをRACEVERSE用能力値として読む。既存本番予測は `src/ranker_production_predict.py` が特徴量数86を検証する。
- `NL_RA_RACE` と `NL_SE_RACE_UMA` は各々約24.3万レース行、290.5万出走馬行を持つ。主キー以外の索引は確認できず、全履歴クエリは重くなる可能性がある。

## 2. 利用可能性と制約

2015年以降の確定JRAデータでは、対象出走馬567,137件、対象レース40,924件を確認した。`Time` と個体別 `HaronTimeL3` は対象出走馬すべてで正値。したがって過去走ラベルとして `E = T - L3` を計算できる。`D600` は同一レース内の `E` 最小値との差として計算できるが、これは残り600m地点の時間差であり、ゲート反応や加速能力ではない。

通過順は全コーナーで均一には揃わない。`Jyuni1c` は42.70%、`Jyuni2c` は48.75%、`Jyuni3c` / `Jyuni4c` は99.17%で有効値を確認した。コーナーのない短距離等を含むため、欠損をゼロや最後方として補完しない。

条件には距離、路面コード、クラス条件コード、賞金、頭数、芝・ダート別馬場状態、レース全体ラップがある。レースデータの `headMakeDate` は `YYYYMMDD` 形式で、発走時刻より前の取得時刻や過去時点の出走表改訂履歴を復元できない。したがって履歴スナップショットは前日までに確定した結果だけを使い、過去の出走表・取消状態の厳密な発走前再現は未解決として扱う。

馬マスタには `Ketto3Info0..13HansyokuNum` があるが、今回の監査では各スロットと父・母・母父との対応を確定していない。血統priorは初版では無効とし、対応関係と時点別利用可能性を別途確認する。スタート直後の個体位置・個体ラップがなく、`start_ability` と `sustain_ability` は推定しない。

## 3. 実装上の決定

1. Horse Profile / BASEは新規の独立系統に置く。Rankerの86特徴量、週次学習、本番予測、既存RACEVERSEは変更しない。
2. 時点スナップショットの基準日は前日終了時点とし、履歴の各結果日は予測日より前に限定する。
3. 時計・末脚・残り600m特徴には、観測値・欠損フラグ・対象レース内の完全観測フラグを残す。発走後の対象レース情報を予測入力に使わない。
4. `start_ability` / `sustain_ability` はNULL相当の未推定とする。血統priorも対応確認とリークテストが完了するまで無効。
5. データ監査で分かった「過去の出走表を発走前状態として再現できない」制約をバックテスト報告に明記し、現行の4,411レースと一致したと主張する前に対象レース集合を照合する。

## 4. 監査コマンド・再現性

件数・カバレッジはローカル `race.db` に対する読み取り専用SQLiteクエリで確認した。フィールド別の分子・分母と利用可否は同階層の `availability.csv` に記録する。DB更新により件数は変わり得るため、結果を固定値としてモデル設定へ埋め込まない。
